# NIIMBOT N1 — драйвер этикеток для Linux

[![Go](https://img.shields.io/badge/Go-1.24+-00ADD8?logo=go)](https://go.dev)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

**Другие языки:** [English](README.en.md) · [Nederlands](README.nl.md) · [简体中文](README.zh-CN.md) · [Pirate 🏴‍☠️](README.pirate.md)

Драйвер термотранспортного принтера этикеток **NIIMBOT N1** по Bluetooth LE.
Написан на Go, работает из командной строки: печатает текст и картинки,
показывает состояние принтера, умеет отрисовать макет без печати.

Никакого приложения вендора, никакого телефона и никаких аккаунтов — только
Linux, Bluetooth и одна команда.

```console
$ niimbot text "1 гульден" "1734"
```

## Возможности

| Команда | Что делает |
|---|---|
| `niimbot info` | состояние принтера и вставленных расходников: id модели, серийный номер, прошивка, заряд, тип этикеток, остаток в рулоне и в ленте |
| `niimbot rfid` | прочитать метки рулона этикеток и ленты (RFID) |
| `niimbot text "строка" "..."` | напечатать текст; каждая строка текста — отдельный аргумент командной строки |
| `niimbot image file.png` | напечатать картинку |
| `niimbot preview "строка"` | отрисовать макет **без печати** — посмотреть, что уйдёт на этикетку |
| `niimbot testpage` | встроенная тестовая страница принтера (проверка связи) |
| `niimbot gui` | графический интерфейс в браузере: **серии этикеток**, шаблоны, предпросмотр |
| `niimbot scan` | найти принтер в эфире |

## Требования

- **Linux** с BlueZ (проверено на Debian и Ubuntu; связь с BlueZ идёт через D-Bus);
- **Go 1.24+** для сборки;
- шрифт с кириллицей (DejaVu, Noto или Liberation — ищутся автоматически);
- принтер **NIIMBOT N1** (для других моделей нужны свои параметры головки — см. «Протокол»).

## Установка

```bash
go install github.com/petrovich811/niimbot@latest
```

Или из исходников:

```bash
git clone https://github.com/petrovich811/niimbot.git
cd niimbot
go build -o niimbot .
```

## Использование

```bash
# посмотреть состояние принтера
./niimbot info

# макет без печати (сохраняется в /tmp/niimbot_label_preview.png)
./niimbot preview "1 гульден" "1734"

# печать текста
./niimbot text "1 гульден" "1734"

# картинка
./niimbot image logo.png

# печать вдвое плотнее, две копии
./niimbot text "ГРК" "инв. 4210" --density 3 --copies 2
```

### Флаги

| Флаг | Значение | По умолчанию |
|---|---|---|
| `--address MAC` | адрес принтера; без него поиск по имени `N1-` | авто |
| `--length мм` | длина этикетки вдоль подачи | `30` |
| `--font точек` | кегль; `0` — подобрать под размер этикетки | `0` |
| `--density 1..3` | плотность печати | `2` |
| `--label` | тип этикетки; **пусто — определить по метке рулона** | авто |
| `--copies N` | число копий | `1` |
| `--flip` | перевернуть содержимое на 180° | выкл. |
| `-v=false` | без подробного вывода протокола | вкл. |

## Графический интерфейс

```bash
./niimbot gui              # поднимет http://127.0.0.1:8765 и откроет браузер
./niimbot gui --port 9000  # другой порт
./niimbot gui --no-browser # только поднять сервер
```

Интерфейс **встроен в сам бинарник** (`embed` + `net/http`), никаких
GUI-фреймворков и внешних зависимостей. Логика печати не дублируется:
интерфейс вызывает те же функции, что и командная строка.

| Что там есть | Зачем |
|---|---|
| **Вкладка «Серия»** | список этикеток — по одной в строке; печать идёт одним заданием, подряд |
| **Загрузка CSV** | из файла берётся первый столбец (Excel сохраните как CSV) |
| **Предпросмотр** | макет этикетки до печати — в файле видно, как ляжет текст |
| **Шаблоны** | сохранённые наборы настроек под типовые задачи: кабельные бирки, шильдики |
| **Состояние** | модель, серийный номер, заряд, тип этикеток, остаток в рулоне и ленте |
| **Прогресс** | «напечатано N из M» по ходу серии |

Разделитель `|` в строке переносит текст на новую строку внутри одной этикетки:
`1 гульден|1734` даст две строки на этикетке: номинал и год.

Шаблоны хранятся в `~/.config/niimbot/templates.json`.

### Серия многострочных этикеток: шаблон + данные

Если каждая этикетка серии должна быть из нескольких строк, есть **шаблон
этикетки** и **таблица данных** — как в настоящих программах для этикеток.

**Шаблон** (поле «Шаблон этикетки»):

```
{1}
{2}
{3}
```

**Данные** (список, одна запись в строке, столбцы через `;`):

```
Зап. Фрисландия;1 гульден 1734;XF
Голландия;1 гульден 1762;VF
Утрехт;2 гульдена 1785;UNC
```

Напечатается **три этикетки по три строки** на каждой:
`{1}`, `{2}`, `{3}` — это столбцы записи.

| Правило | Как работает |
|---|---|
| Строки шаблона | каждая строка шаблона = строка на этикетке; пустые строки в конце отбрасываются |
| Столбцы | разделитель `;`, `,` или табуляция — что встретится первым |
| Повтор столбца | `ТЕГ {2}` — столбец можно ставить в любом месте строки |
| Без шаблона | одна строка данных = одна этикетка, а символ `\|` внутри переносит текст |

Так CSV из Excel подходит напрямую: загрузили файл, задали шаблон — и вся
таблица ушла на печать серией.

### Печать серии из Excel

1. В Excel сделайте таблицу: **одна строка — одна этикетка**, столбцы — то, что
   попадёт на бирку.
2. Сохраните как **CSV**: «Файл» → «Сохранить как» → CSV.
3. В интерфейсе на вкладке «Серия» нажмите **Загрузить CSV** — строки попали в список.
4. Задайте **шаблон этикетки** со столбцами `{1}`, `{2}`… — он определяет, как
   выглядит этикетка.
5. Посмотрите **Предпросмотр** и нажмите **Печать**.

Галочка «первая строка — заголовки» отбрасывает шапку таблицы. Кавычки защищают
разделитель внутри поля: `"KM# 90; Verkade 45.2";XF` — это два столбца, а не три.

**Про столбцы.** Их должно быть **не меньше**, чем самое большое число в шаблоне:
шаблон с `{3}` требует трёх столбцов. Excel дополняет пустые ячейки сам, поэтому
`Зап. Фрисландия;;XF` — это три столбца, и на этикетке останется **пустая строка**:
раскладка у всех этикеток серии одинаковая. Лишние столбцы игнорируются. Если
столбцов меньше, драйвер **откажется печатать** и скажет, какого не хватает —
вместо того чтобы напечатать на этикетке литеральное `{3}`.

**Порядок столбцов.** Если в таблице столбцы идут не в том порядке, как нужно на
этикетке, переставлять их в Excel не обязательно — впишите номера столбцов сверху
вниз, через запятую:

```
4, 1, 2, 5
```

Это значит: первая строка этикетки — столбец 4, вторая — 1, дальше 2 и 5. Столбец,
который не упомянут (здесь третий), на этикетку не попадёт; один и тот же столбец
можно указать дважды. Поле «Шаблон этикетки» заполнится само — `{4}`, `{1}`, `{2}`,
`{5}` — и его можно потом дополнить, например `ТЕГ {2}`.

## Этикетки и ориентация

### Виды этикеток

Протокол NIIMBOT знает восемь типов этикеток, но **N1 поддерживает пять**
([описание типов](https://printers.niim.blue/other/label-types/)):

| Код | Тип | N1 |
|---|---|---|
| 1 | с зазорами — обычные (`withgaps`) | ✅ |
| 2 | чёрные термочувствительные (`black`) | ❌ |
| 3 | непрерывная лента (`continuous`) | ✅ |
| 4 | перфорированные (`perforated`) | ❌ |
| 5 | прозрачные (`transparent`) | ✅ |
| 6 | ПВХ-бирки (`pvctag`) | ❌ |
| 10 | с чёрной меткой (`blackmarkgap`) | ✅ |
| 11 | термоусадочная трубка (`heatshrink`) | ✅ |

В протоколе есть типы `black`, `perforated` и `pvctag`, но прошивка N1 их
не поддерживает. Драйвер проверяет тип **до подключения** к принтеру и отказывается
печатать, если модель его не поддерживает.

Для N1 продаются этикетки шириной **до 15 мм** (печатаемая часть — 12 мм
по центру): белые матовые 14×30, 14×40 и 14×50 мм, матовое серебро и
прозрачные 14×30 мм, кабельные 12,5×109 мм четырёх цветов. Печать
термотранспортная — нужна красящая лента (риббон).

### Автоопределение расходников

В каждом рулоне — и этикеток, и ленты — стоит **RFID-метка**. Принтер читает
её сам, а драйвер умеет спросить:

```console
$ niimbot rfid

=== рулон этикеток ===
  UUID:                  881dcce946121080
  штрихкод:              12242117
  серийный номер:        PC0H902384002378
  тип этикетки:          withgaps (1) — N1 поддерживает
  ресурс:                228, израсходовано 43, осталось 185

=== лента (риббон) ===
  UUID:                  881d8209fa900000
  серийный номер:        PZ1GA06304000391
  ресурс:                1600, израсходовано 901, осталось 699
```

**Тип этикетки определяется автоматически.** Если `--label` не задан, драйвер
читает метку рулона и берёт тип оттуда: принтер знает, что в него вставлено,
лучше любой догадки. Если тип из метки модель не поддерживает, печать не
начнётся. Если `--label` задан явно и расходится с меткой, драйвер предупредит:

```
внимание: в принтере этикетки типа withgaps, а печатаем как continuous
```

Длину этикетки метка тоже хранит, но принтер **не отдаёт её хосту** (вендорное
приложение берёт размеры с сервера по номеру рулона), поэтому длину по-прежнему
задают флагом `--length`.

### Ориентация

Принтер N1 печатает головкой на **96 точек** — это **12 мм** при 203 dpi.
Здесь используются этикетки **EW14×30**: 14 мм по ширине и 30 мм по длине
вдоль подачи. Печатаемая часть — 12 мм по центру этикетки.

**Текст идёт вдоль этикетки.** Чтобы так получилось, содержимое рисуется
в «ориентации чтения». В ней ширина картинки — это длина этикетки,
а высота — ширина головки. Дальше картинка превращается в строки принтера:

- **транспонируется** — ось X картинки становится направлением подачи;
- **ось головки идёт в обратном порядке** — точка головки `c` берётся
  из строки картинки как `across-1-c` (в NiimBlueLib это
  `idx = (height-1-col)*width + row`).

Обе тонкости проверены печатью на живом принтере, и обе были ошибками автора:

1. если рисовать «как на экране», текст ложится **поперёк** этикетки;
2. без разворота оси головки этикетка выходит **зеркальной**.

Если этикетка печатается перевёрнутой, добавьте `--flip` — это поворот на 180°.

## Протокол

Пакет:

```
55 55 | команда | длина | данные | XOR-контроль | AA AA
```

Многобайтовые числа — **big-endian**. Контрольная сумма — XOR команды,
длины и всех байт данных.

Цикл печати:

```
плотность (0x21) → тип этикетки (0x23) → старт печати (0x01) →
старт страницы (0x03) → размер страницы (0x13) → строки битмапа (0x85) →
конец страницы (0xE3) → опрос статуса (0xA3) → конец печати (0xF3)
```

Строка битмапа: `позиция(2) | счётчики чёрных точек(3) | повторы(1) | данные(12)`,
где бит 7 первого байта — крайняя точка головки. Полностью белые строки
отправляются отдельной командой `0x84` — это короче и быстрее.

Статус печати (ответ `0xB3`): `страница(2) | прогресс печати % | прогресс подачи %`.
Печать завершена, когда оба прогресса равны 100.

### Две тонкости серийной печати

Обе найдены на живом принтере и обе стоили сорванных этикеток:

**1. Между строками битмапа нужна пауза** (здесь — 4 мс). `writeWithoutResponse`
отдаёт данные быстрее, чем принтер успевает их принять, и он отвечает ошибкой
данных: ответ `0xDB`, код `6`. Без паузы срывается уже вторая этикетка серии.

**2. Между этикетками нужно ждать завершения страницы.** Пока принтер печатает
предыдущую этикетку, следующая для него — лишние данные, и он снова отдаёт
ошибку `0xDB`/`6`. Драйвер опрашивает статус и ждёт двух подряд замеров
«100 % печати и подачи», только потом шлёт следующую.

Полезно и то, что **ошибка `0xDB` читается**: драйвер расшифровывает код
(открыта крышка, нет бумаги, перегрев, нет ленты и так далее) и прекращает
задание, вместо того чтобы молча ждать таймаута.

### Две ловушки, на которые стоит обратить внимание

**1. У принтера два BLE-сервиса, и рабочий только один.**

| Сервис | Что это |
|---|---|
| `e7810a71-73ae-499d-8c15-faa9aef0c3f2` | **родной сервис NIIMBOT** — его слушает прошивка, характеристика `bef8d6c9-9c21-4c9e-b632-bd58c1009f9f` |
| `49535343-fe7d-4ae5-8fa9-9fafd205e455` | прозрачный UART — подходит по свойствам (`notify` + `write`), но **на команды не отвечает вообще** |

Подключение к UART выглядит успешным, но принтер молчит: команды уходят
«в пустоту». Именно из-за этого при отладке тратится больше всего времени.

**2. BlueZ нужно сначала «увидеть» устройство.**

Без предварительного сканирования подключение падает с ошибкой D-Bus:

```
Method "Get" with signature "ss" on interface "org.freedesktop.DBus.Properties" doesn't exist
```

Плюс важная деталь для Go: `Adapter.Scan` у Linux-бэкенда библиотеки
`tinygo.org/x/bluetooth` **блокируется до `StopScan`** — его нужно запускать
в отдельной горутине, иначе программа зависнет.

### Другие модели

Параметры привязаны к N1: id модели `3586`, головка `96` точек, плотность `1..3`.
Для другой модели нужно поменять эти значения в `protocol.go`
(таблица соответствий «модель → параметры» есть в
[NiimBlueLib](https://github.com/MultiMote/niimbluelib/blob/master/src/printer_models.ts)).

## Тесты

```bash
go test ./...
```

Тесты проверяют сборку пакетов **сверкой с байтами, снятыми с живого принтера**
(рукопожатие `5555c10101c1aaaa`, запрос модели `555540010849aaaa`), разбор
ответов, склейку неполных пакетов, счётчики точек, ориентацию строк
и белый фон холста.

## Что проверено, а что нет

**Проверено на живом принтере N1 (GA24110447):**

- поиск, подключение и рукопожатие;
- id модели `3586`, серийный номер, прошивка `3.13`, заряд;
- **печать текста** — полный цикл: `страница 1, печать 100%, подача 100%`;
- **печать картинки** — рамка, текст и метка в углу легли так же, как на макете;
- **ориентация** — оттиск читается правильно: текст вдоль этикетки,
  не зеркальный. Подтверждено на бумаге после двух исправлений,
  описанных выше;
- обе ошибки ориентации обнаружились именно при печати: без физического
  оттиска их не выявить.

**Пока не проверено:**

- печать на других типах этикеток (`--label`), кроме `withgaps`;
- другие модели NIIMBOT (нужны свои параметры головки).

## Сборка под другие системы

Драйвер написан на Go, поэтому собирается под Linux, Windows и macOS:

```bash
go build -o niimbot .                                  # своя система
GOOS=windows GOARCH=amd64 go build -o niimbot.exe .    # Windows, из Linux тоже
GOOS=darwin  GOARCH=arm64 go build -o niimbot-mac .    # macOS — ТОЛЬКО на Mac
```

| Система | Состояние |
|---|---|
| **Linux** | работает, проверено на живом принтере |
| **Windows** | собирается из Linux без правок; на живом принтере пока не проверялось |
| **macOS** | **собирать нужно на Mac**: там Bluetooth — это CoreBluetooth, а её привязка требует CGO и фреймворков Apple. Кросс-сборка из Linux невозможна |

**Особенность macOS:** система не отдаёт настоящие Bluetooth-адреса — вместо MAC выдаёт UUID. Поэтому на Mac принтер ищется сканированием, а `--address` принимает UUID, а не MAC.

**Шрифт** ищется сам: DejaVu/Noto/Liberation в Linux, Arial/Segoe UI в Windows, Arial/Helvetica в macOS. Свой можно задать переменной `NIIMBOT_FONT`.

## Смежные проекты

Если Linux рядом с принтером нет, есть и другие пути:

| Проект | Что даёт |
|---|---|
| [NiimBlueLib](https://github.com/MultiMote/niimbluelib) | открытая библиотека протокола NIIMBOT (JS, MIT) — на ней построен и этот драйвер |
| [NiimBlue](https://niim.blue/) | готовый веб-клиент: печать из браузера по Web Bluetooth, **без сервера**. На Android работает в Chrome, на iPhone нужен браузер [Bluefy](https://apps.apple.com/us/app/bluefy-web-ble-browser/id1492822055) |
| [NiimPrintX](https://github.com/labbots/NiimPrintX) | клиент на Python с графическим интерфейсом; модели D11, B21, B1, D110, B18 — N1 в списке нет |

Этот драйвер отличается тем, что работает из командной строки на Linux и умеет
**серии этикеток из CSV с шаблоном**.
